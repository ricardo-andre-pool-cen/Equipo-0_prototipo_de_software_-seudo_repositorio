## FIRST PART (5:00 MIN): EXPLANATION OF THE PRODUCT

- ### What is it?, why is important?

  - pool
  - luis

>**No face -  Pool**: Greetings to the viewers, we are team#0 and we are about to present all our journey along the Software Engineering Fundamentals subject.

---

>**Face - Pool**: So powerful tool that is git, am i right? however learning how to use it is difficult for most beginning people, this isn't because there is no information about it, but most of those are huge complex blocks of text, or doesn't introduce the viewer to all posible information, so a person could not understand what git can do, they don't finish comprehending the power of this tool.

---

>**Face - Luis**: So, with that in mind, we saw value in a new environment that could put together all posible information about git, and presented in different formats than just text, in order to help beginning users learning git to comprehend it, but also to any person that would love to learn all it's functions and usefulness.

- ## Use cases

  - perla
  - katherine

>**Mixed - Katherine**: Once we got to know what type of people are supposed to use the product, we wrotte the requirements, we had to make sure that this new environment will be easy to navigate since it's supposed to contain tons of information, it would also need to be visually lighter. We used scrum artifact user stories to display the requirements as if a real user would be telling us what does he need, and we specify them in use cases that describe the main process to explore the environment.

---

>**Mixed - Perla**: We set a common information organization that would be easy to understand: big, medium and small containers, while the user gets to explore from bigger to smaller containers, the information would start appearing bigger, and it would be presented as playable audios, graphs, images, diagrams icons and animations, but not only that, the user will also be able to perform knowledge tests inside the environment so he doesn't only learns but tests himself, finally a user would be able to access these big containers with just one or two steps from the home page.

- ## Design

  - pool
  - jaime

>**Face - Pool**: These information were our instructions to build the prototype. This is the first impression of how the environment would look like.

---

>**No face - Pool**: Designed for web, in the home page there is the direct access to the containers, but it would take the user just to the beginning, if he would like to go deeper, he can use the intelligent search bar that would take him in the right big container where the information he wants is, or he can scrolldown to this diagram that shows all the structure of the environment with direct links, this assure that the user only takes one our two steps to access the containers.
